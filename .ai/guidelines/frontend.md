# Frontend Structure

## Directory Map (`resources/js/`)

| Path                                | Contents                                                                                             | Rules                                                                                                                                             |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app.ts`                            | Inertia app bootstrap                                                                                | Do not add page logic here.                                                                                                                       |
| `pages/`                            | Inertia pages, one per `Inertia::render()` name                                                      | Subfolders are lowercase by domain (`auth/`, `settings/`); files are PascalCase (`settings/Profile.vue` ↔ `Inertia::render('settings/Profile')`). |
| `layouts/`                          | Page layouts (`AppLayout.vue`, `AuthLayout.vue`, `settings/Layout.vue`, variants in `app/`, `auth/`) | Pages pick layouts via `defineOptions({ layout: ... })`.                                                                                          |
| `components/`                       | App-level components (`AppSidebar.vue`, `InputError.vue`, `Heading.vue`, ...)                        | PascalCase file names; one component per file.                                                                                                    |
| `components/ui/`                    | shadcn-vue primitives (button, input, dialog, ...)                                                   | Generated by shadcn-vue CLI. Do not hand-edit; add new ones with `npx shadcn-vue@latest add <name>`.                                              |
| `composables/`                      | Reusable stateful logic (`useAppearance.ts`, `useInitials.ts`)                                       | File and export named `useSomething`.                                                                                                             |
| `lib/`                              | Pure helpers (`utils.ts` with `cn()`, `flashToast.ts`)                                               | No Vue state here.                                                                                                                                |
| `types/`                            | Shared TS types (`auth.ts`, `navigation.ts`, `ui.ts`, `global.d.ts`)                                 | Re-export new type files from `types/index.ts`.                                                                                                   |
| `actions/`, `routes/`, `wayfinder/` | Wayfinder-generated code                                                                             | Git-ignored and generated. Never edit by hand.                                                                                                    |

## Vue Components

- Always use `<script setup lang="ts">`.
- Component files and names are PascalCase (`NoteCard.vue`). Domain components may be grouped in `components/<domain>/` (e.g. `components/notes/NoteCard.vue`).
- Every component has a single root element in its template.
- Import with the `@/` alias (e.g. `@/components/ui/button`), never long relative paths.

## Typing

- Type props with `defineProps<{ ... }>()`; type emits with `defineEmits<{ ... }>()`.
- Every page declares a props type matching the data passed by `Inertia::render()`. Shared domain types (e.g. `Note`) go in `types/<domain>.ts` and are re-exported from `types/index.ts`.
- Shared Inertia props (`auth.user`, etc.) are typed in `types/global.d.ts`; extend that file when `HandleInertiaRequests::share()` changes.
- No `any`. Use `unknown` plus narrowing when the shape is truly unknown.

## Routing (Wayfinder)

- Never hard-code URLs. Import controller actions from `@/actions/...` (e.g. `import NoteController from '@/actions/App/Http/Controllers/NoteController'`) or named routes from `@/routes/...` (e.g. `import { edit } from '@/routes/profile'`).
- After adding or changing routes, regenerate with `php artisan wayfinder:generate` (the Vite plugin also regenerates during `npm run dev`).

## Forms

- Default: Inertia's `<Form>` component bound to a Wayfinder form variant, as the starter kit does: `<Form v-bind="ProfileController.update.form()" v-slot="{ errors, processing }">` (see `pages/settings/Profile.vue`).
- Use `useForm()` when the form needs programmatic control (computed fields, client-side transforms, reset/submit from script, multi-step state). Pass Wayfinder URLs to it, e.g. `form.submit(store())`.
- Show field errors with `components/InputError.vue`.
- Disable submit buttons while `processing` is true.

## UI Components

- Before creating a component, check `components/ui/` (shadcn-vue) and `components/` for an existing one.
- Missing primitive available in shadcn-vue → add it via the CLI (`components.json` is configured) instead of writing a custom one.
- Icons come from `@lucide/vue`. Merge classes with `cn()` from `@/lib/utils`.
- Style with Tailwind CSS utility classes; avoid scoped `<style>` blocks unless Tailwind cannot express the rule.
